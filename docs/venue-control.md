# 匹配日会场

女性共创 → 预孵化营 → 体验会场彩排。在已发布排班的活动详情页，报名成员和运营可从「进入本场会场签到」进入真实场次。无活动标识的彩排仅在当前页面内运行，使用虚构名单。

## 主持人操作

1. 事先发布排班。提醒参与者活动前半小时可以确认真实姓名并签到。姓名由本人填写，只有总主持人与排定的会面对象能在会场查看签到姓名。
2. 开场后更新共享文字讲稿，所有房间在下一次同步时看到更新。点击「结束讲解，开放分组」后，项目方与伙伴分别确认抵达自己的房间。总主持可恢复全场讲解。
3. 每轮十五分钟，换场两分钟。项目方在双方到房之后可以提前结束该次会谈。下一场仍按排班开始。时间到只结束本系统的会谈时段。是否在场以主动确认记录为依据，浏览器关闭无法作为离场证明。
4. 核对轮换表后结束整场。正式场次的控制状态保存在活动记录中。彩排可以切换三种角色、跳轮或重新开始。

## 代码与数据

界面位于 Sites 源码的 `app/venue.tsx`，状态变更规则位于 `app/venue-control.ts`。匹配日接口的 `view=venue` 返回本人的有效安排或运营总览。客户端每五秒同步一次，倒计时按服务端时间校准。写入核对登录身份、活动授权、活动版本和原定轮次。并发冲突后先读取最新状态，由操作者判断是否重试。旧活动缺少会场字段时以开场讲解状态读取。

## 媒体接入与验收

本版交付文字讲稿、签到和轮换协调。接入音视频后还要验证设备预检、总主持播报、房间级订阅、跨网络重连及旧房间媒体撤销。数据库占位在媒体关闭得到确认后释放。控制页提前结束、离开网页或倒计时归零都不能代替供应商的关闭确认。

上线彩排使用独立的主持人、项目方和伙伴设备，重点观察无人在房、提前结束、超时、掉线与未授权收听。通过同机角色切换无法证明真实多人媒体连通或容量。

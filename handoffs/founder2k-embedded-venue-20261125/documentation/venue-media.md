# 会场媒体方案、费用模型与验证边界

2026-11-21。未购买服务、未产生媒体用量、未执行收费压测。目标为互动 100 人 / 20 个并行分组 / 4 小时；路演 500 位观众 / 最多 10 位台上 / 4 小时。以下并非实测容量。

## 官方证据与方案

已通过 GitHub 读取 LiveKit 官方 protocol 的 `livekit_room.proto`；其中 `ForwardParticipant` 明确为 Cloud-only，可将同一参与者轨道转发至多个房间，在目标房间调用 `RemoveParticipant` 或源离开时终止转发；`MoveParticipant` 同样为 Cloud-only。这证明 API 契约存在，不证明本账户套餐可用、配额足够或实际媒体隔离已通过。

官方协议来源：[livekit/protocol](https://github.com/livekit/protocol/blob/fb74d2fd0aecd2418fa2185bb59f637be736d587/protobufs/livekit_room.proto)。官方开源服务：[livekit/livekit](https://github.com/livekit/livekit)。商业信息待核实：[LiveKit pricing](https://livekit.io/pricing)、[LiveKit docs](https://docs.livekit.io/)、[Daily pricing](https://www.daily.co/pricing/)、[Daily docs](https://docs.daily.co/)。本环境访问定价官网和 founder2k.com 时收到代理 CONNECT 403，未取得当前报价；不能将历史价格写成当前官方报价。

| 方案 | 多房间分发与停止 | 长会话与隔离要验证 | 取舍 |
|---|---|---|---|
| LiveKit Cloud，首选候选 | 主持人独立源房间，转发其屏幕和声音到获准分组；每组独立 RemoveParticipant 停止；分组媒体不向源转发 | 逐组撤销后不能凭旧 token 重连；主持人掉线重进后重新转发；四小时续期、设备替换、各组媒体订阅对账 | API 与需求贴合，但须确认套餐是否开放、转发身份如何计费、人数/带宽限额 |
| Daily 托管，比较候选 | 每组独立 room；另设只读演示源连接或服务端媒体桥。原生跨房转发能力未核实 | 同一客户端双连接对手机资源影响、逐组撤销能力、旧 token 失效、房间时限 | 不把普通嵌入会议组件视为已满足调度；需自定义界面和服务端授权 |
| LiveKit 开源自托管 | 无上述 Cloud-only 原生转发承诺；可自建单向媒体桥，每目标房有发布代理，或独立只读演示连接 | 需要真正撤销演示订阅而非 UI 静音；SFU/TURN、桥重启、区域、TLS/UDP、Redis/多节点、四小时故障恢复 | 可控但运维及桥接工程量高；Worker 不能直接当作 UDP SFU，需要额外主机 |

所有方案均默认不录制。演示桥身份必须仅允许主持源发布，不能订阅分组私聊后再次分发。团队讨论会话与只读演示会话若双连接，会增加计费连接分钟和设备负载。路演可评估只读 WebRTC 与直播分发两种模式；直播有延迟，不能用于要求即时互动的会谈。转播服务、CDN、转码与出站费单列。

## 单场成本模型

用量基线按全员在线 240 分钟计算。互动 100 人合计 **24,000 参与者分钟**。路演按 500 位观众另加 10 位台上计算 **122,400 参与者分钟**；若 500 是含台上的总人数则为 120,000。主持人/媒体桥/双连接如未包含需另加。

| 方案 | 互动单场 | 路演单场 | 尚缺报价 |
|---|---|---|---|
| 按参与者分钟托管 | 24,000 × 单价 + 演示附加连接 + 最低套餐/其他费用 | 122,400 × 单价 + 附加项 | 当前阶梯价、免费额度、转发身份计费、合同最低承诺、税 |
| 按分钟及出站计价托管 | 24,000 × 分钟价 + 实际 GB × 出站价 + 固定套餐分摊 | 122,400 × 分钟价 + 实际 GB × 出站价 + 固定套餐分摊 | 地区、码率、多订阅、TURN 与转发处理费 |
| 自托管 | 4 × 节点数 × 小时价 + 演示桥小时费 + 出站 + TURN + 运维 | 同式，按舞台总码率/订阅数增容 | 实际主机规格和地区价格、峰值能力、冗余和公网转发成本 |

仅作预算敏感性示例，**不是任何厂商报价**：若单价 $0.004/参与者分钟，互动基线 $96，路演基线 $489.60；实际采购必须用当日官方单价替换。若每个分组有一个计费转发身份且连续四小时，20 × 240 = 4,800 附加分钟；若全体另开一条四小时演示连接，则再增加 24,000 分钟。实际开场演示较短时按实际时长计算。

带宽预算用每位接收者所有轨道合计码率，避免将十位台上误算成一条轨道。假设平均下行合计 1.5 Mbps（待实测），每人四小时约 2.7 GB，100 人约 270 GB，500 位观众约 1,350 GB；尚未含舞台接收、协议开销和冗余。自托管出站若假设 $0.09/GB，则仅这部分分别 $24.30 / $121.50，加主机和运维；这些同样是假设，不是官方套餐价格。

不得据上述示例开通服务。取得官方报价后，先向用户列明小规模真实媒体彩排的人数、时长、附加转发、金额上限和用途，再申请新增付费服务；100/500 人、四小时负载测试另列预算。未核实价格、套餐能力及费用上限之前，只能准备测试方案。

## 选型准入验证

1. 以两间隔离房、独立账号、主持屏幕和声音证明分发；A 单独停止一分钟后 B 才停止。记录订阅轨道、音频哨兵和每组接收证据。
2. A 私聊后，B 不能订阅 A 的任何轨道；A 不能凭旧演示凭证恢复订阅。前端隐藏按钮不算授权测试。
3. 源主持重连、目标房重连、音视频切换、TURN 路径、手机锁屏/回前台及四小时续期都需单独验证。测试媒体 token 到期不会被错误当成断开机制。
4. 服务端硬截止、撤销失败与媒体 webhook 乱序/重复情况下，新访客不得进入旧会话；能向主持人显示异常并恢复。
5. 选择方案前记录实际客户端数、峰值下行、服务端/供应商配额和最低可接受网络条件。将结果写入[验证报告](venue-validation.md)，不将官方功能列表当作实测结果。

## 2026-11-22 官方费率复核

以下预算均为美元，按每人完整在线四小时，忽略税费及站点计算成本。主持及转发的额外连接另计。两种活动的月度免费额度分别独立举例；同月连续举办时应先扣除已用额度。

| 服务与用量 | 100 人互动 | 500 观众加 10 位台上 |
|---|---:|---:|
| Cloudflare RealtimeKit 全音视频，月度包含额度已用完 | 24,000 分钟 × $0.002 = $48 | 122,400 分钟 × $0.002 = $244.80 |
| 同服务，本月尚余 10,000 音视频分钟 | $28 | $224.80 |
| Cloudflare Realtime SFU，平均每人下行共 1.5 Mbps，免费额度已用完 | 270 GB × $0.05 = $13.50 | 1,377 GB × $0.05 = $68.85 |
| 同 SFU，本月尚余 1,000 GB | $0 | $18.85 |

RealtimeKit 按 preset 的会议类型计费；在客户端关摄像头不一定改变单价。SFU 与 TURN 共用月度 GB 额度。Cloudflare 两个方案均需另行实现与验证房间授权及逐组停止分发。官方文档来自 [RealtimeKit 价格](https://developers.cloudflare.com/realtime/realtimekit/platform/pricing/) 和 [Realtime SFU 价格](https://developers.cloudflare.com/realtime/sfu/platform/pricing/)。

实际彩排采用开源 LiveKit，本地 SFU 未开通付费服务，新增供应商费用 $0。公网自托管总成本取决于主机、出站、TURN 与运维。LiveKit Cloud 的多房间转发接口已核对，当前账户的套餐、配额与最终价格尚未核实。

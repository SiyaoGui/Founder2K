# 私密活动会场交接与本地彩排

基线为 Sites 的 Founder2K 项目 `appgprj_6aff90e2aa188191b3577b40fae2533b`，源码归档标识为 `8205b6801de8017dbb9ed23033bddb8971822a52`。会场入口使用原网站的 `/venue?id=<活动 ID>`。女性共创从已发布活动进入，创业快闪、导师答疑和路演从已录取场次进入。运营在场次编辑页选择会场形式。成员用报名姓名签到。

## 主持人操作单

1. 从活动详情进入。核对开场时间、接班人和替补。请每个人从自己的账户签到，打开「入场前测试设备」。成员自己选择是否自动转场。姓名默认标注「本人声明」，运营完成核验后才能标记为已核验。
2. 点击「共享演示与主持人声音」，选择演示窗口并授权麦克风。现场接收者必要时点击「播放声音」。调度台列出各组演示源信号，房内成员还须实际听看确认。
3. 勾选目标组，核对预览后立即交棒或倒计时 30 秒。接班人离线时先选替补或暂代。通知只发文字。恢复演示及全场召回会终止受影响会谈，确认前查看参与者和范围。
4. 先看超时和求助。点开该组的下一位及更新时间，联系状态待确认的人。成员可登记补谈，管理员可申请补位。正常入场从个人议程操作。提前开始要求双方先结束上一场并分别同意。成员可以随时跳过或离场。
5. 结束后由双方处理补谈或试合作意向。女性共创的建队仍经过原活动的邀请、接受和运营审核。通过后进入主站团队工作台。

## 从活动页进入私密彩排

总主持人在正式活动会场点击「创建独立彩排场次」会进入新的彩排。成员可以从原活动会场的签到页进入最近一次彩排，或用主持人提供的本次彩排地址进入。每次读取都检查原活动的报名或录取权限。个人配对来自原活动发布排班，签到、主持权、房间、通知和会谈记录使用新的实例 ID。彩排结束后返回正式会场。每次创建都会得到新的实例，不清空旧数据。

## 可重复的本地入口

在集成源码根目录执行以下命令。Linux 彩排需要 Node 22.13 以上、Chromium、LiveKit Server 及可写的临时目录。已测媒体服务为 LiveKit Server 1.13.11。使用 GitHub 对应版本的官方校验和验证二进制文件后，把它加入 PATH 或设置 LIVEKIT_SERVER。CHROMIUM 可指定浏览器路径。启动脚本只在本机创建合成成员、临时数据库和测试凭据，每次生成新的活动 ID。

```sh
npm ci
npm run build
node --test tests/venue-occupancy.test.mjs
node tests/rehearsal/run.mjs
```

浏览器用独立上下文分别表示主持人、两个项目方及一位伙伴。测试只向回环 Worker 的请求提供合成身份。真实站点继续依赖原平台已认证的请求身份。会场媒体经过本机 SFU。彩排发送带有画面标记的演示视频、440 Hz 主持人音频和 880 Hz 私聊音频，在接收端读取视频尺寸和声音频谱。手机布局使用 390 像素宽的 Chromium 视口。

## Sites 环境中的运行依赖

按原项目方式连接 DB，保留 0000 至 0002 的迁移，在同一数据库追加 0003。生产媒体服务须提供浏览器可达的 WSS、公网 ICE/TURN、有效 TLS 和服务端可达的管理 API。本地实现采用分组独立演示房和每场唯一私聊房，开源 LiveKit 配置要求 `room.auto_create: false`。屏幕和声音按目标组分别发布，因此主持人上行和编码成本随演示组数增加。20 组容量须实测。

Worker 的安全设置中配置 LIVEKIT_URL、LIVEKIT_API_KEY、LIVEKIT_API_SECRET、VENUE_CLOCK_KEY 和原有 FOUNDER2K_ADMIN_EMAIL。LiveKit 将签名事件发到现有站点的 /api/venue/webhook。媒体主机使用同一 VENUE_CLOCK_KEY 并配置 VENUE_SITE_URL，在进程监管下运行 `node scripts/venue-clock.mjs`。它负责服务端截止和媒体撤销；调度服务近期无心跳时，系统拒绝新增私聊。网络故障导致媒体端撤销失败时需要恢复服务并核对会谈，再安排后续入场。

发布应使用目标 Sites 项目的短期仓库凭据，核对项目与当前线上提交，合入补丁、构建并执行迁移，再验证私密活动入口。本会话无 Sites 发布连接器和实际发布回执。远端协作文档写入权限单独核验。

## 快闪团队编组彩排

运行集成源码中的 `node --experimental-strip-types --test tests/venue-grouping.test.mjs` 检查三种分发模式与部分重排。`node tests/rehearsal/run.mjs --teams-only` 从主持人界面全选分发、确认发布、交棒和拖动成员，同时检查主会场与两间讨论组的收听结果。`node tests/rehearsal/run.mjs --many-teams` 使用本地 SFU 为 100 名合成成员编排 20 组，每组连接两名音频成员，在同一检查中比较 20 个接收端。两个命令沿用前文的 Chromium、LiveKit 和构建要求。

交付包内的 `Founder2K-team-planner-demo.html` 可离线操作同一套编组组件，包括全选、标注、三种分发与拖动。示例的发布只更新当前页面。真实会场从活动页进入并写入本场数据库。

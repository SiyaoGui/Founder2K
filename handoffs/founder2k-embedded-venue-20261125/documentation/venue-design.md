# 内嵌式活动会场：界面与实时执行协议

2026-11-22。此文记录交互设计和执行规则，示例姓名和项目均为虚构。当前已从 Sites 提交 8205b68 接入认证、女性共创发布排班、快闪录取和团队数据、本地 D1 与开源 LiveKit。实际覆盖范围以[测试报告](venue-validation.md)为准。线上未发布。

## 三个核心界面草图

### 参与者：桌面

```text
女性共创 · 匹配日         陈澄 · 开发贡献者 · 姓名本人声明    [私下求助] [离场]
当前由 林悦 主持          服务器时间 15:46:00              [收起议程]
┌──────────────────────────────────┬───────────────────────────────┐
│                                  │ 我的议程 · 第 3／6 场          │
│    全场演示 / 当前获准会谈          │ 现在：与林悦讨论无障碍硬件       │
│                                  │ 项目缺口：原型开发与设备测试     │
│  林悦 · 项目发起人                 │ 15:42–15:57 · 还剩 11 分钟      │
│  陈澄 · 开发贡献者                 │ 现场：双方已连入 · 刚刚更新      │
│  管理员或导师进入时显示姓名和角色    │ 1 已完成 / 2 空档 / 3 进行中     │
│                                  │ 4 与安宁讨论社区服务 · 15:59    │
│                                  │ 对方仍在上一场 · 5 秒前更新      │
│                                  │ 5 计划见面 / 6 计划见面         │
├──────────────────────────────────┤ [查看完整议程] [登记补谈]       │
│ 麦克风 摄像头 共享屏幕 纯音频       │ [结束本次] [跳过本轮]           │
└──────────────────────────────────┴───────────────────────────────┘
```

首屏固定显示“现在做什么、下一位及预计可进入时间”。下一位仍忙时显示“预计 15:59；等待对方结束，尚不可进入”，不能用倒计时归零暗示必然可进。六条议程逐条同时显示计划时间/轮次/进度和现场状态/更新时间；空档保留。延长或调度变更同时保留原计划与最新安排，提示原因。发起人留在固定逻辑房间，看六位来访者、当前等待时长及下一位的准备意愿。

### 参与者：手机

```text
女性共创  陈澄                [求助] [离场]
┌──────────────────────────────────────┐
│           演示或当前会谈                │
│       当前主持：林悦                    │
│       所有实际在场者姓名、身份           │
└──────────────────────────────────────┘
[麦克风] [摄像头] [更多设备与共享操作]
┌ 始终可见，含安全区，展开不遮挡离场 ────────┐
│ 现在 与林悦讨论无障碍硬件 · 剩余 04:00    │
│ 下一位 安宁 · 15:59 · 对方仍在上一场      │
│ [展开六场议程]                          │
└──────────────────────────────────────┘
```

展开为可关闭抽屉，键盘焦点进入并在关闭时返回按钮；状态不只用颜色。按钮至少 44px，390px 宽时不横滚。屏幕阅读器仅在阶段变化与一分钟/十秒提醒时播报，避免每秒播报倒计时。设备权限失败给出重试、纯音频或重新入场；手机浏览器屏幕共享能力按设备验证，不承诺所有手机均可发起共享。

### 分组管理员

```text
我的组 · 无障碍硬件       当前控制权：总主持人 周禾
30 秒后交棒给你           [确认已准备] [向总主持人求助]
当前：林悦、陈澄          实际连通 15:42:18 · 硬截止 15:57
下一位：安宁              仍在上一场，15 秒前更新
候场：1 人                无权接收当前房内媒体
异常：连接待确认 / 等待 02:14 / 演示信号未确认
[接待获准来访者] [申请补位] [本组设备排查] [申请延长]
```

接待不能覆盖房间占用。补位只提交请求，不悄悄改变对方议程。项目发起人和管理员权限分别授予。管理员离线时交棒保持待确认，列入总台异常；总主持人选择暂时代管或指定有权限且在线的替补。

### 总主持人

```text
调度台  2 组等人超过两分钟 · 1 组演示信号中断
[处理等待] [查看信号异常] [查看全部房间]
开场覆盖：16 组演示中 / 3 组已交棒 / 1 组连接异常
选定：无障碍硬件、社区服务  [现在交棒] [倒计时后交棒]
[发一条全场通知] [恢复向指定组分发演示] [结束分组并召回全场]
房间表：当前主持 / 阶段 / 正在会谈 / 下一位 / 等待时长 / 媒体确认
```

通知默认文字，保留会谈；语音通知需要明确选择，不能冒充普通通知。恢复演示和召回先展示房间、在场者、被打断会谈和后续影响，提交带预览版本的确认；版本变化必须重新预览。广播操作不得捆绑这三个动作。

## 角色、姓名与可见范围

| 身份 | 可见 | 可操作 |
|---|---|---|
| 参与者 | 自己六场、预约对象必要状态、自己获准房内成员 | 签到、设备测试、准备好、提前开始同意、跳过、离场、私下求助 |
| 项目发起人 | 自己来访队列及项目缺口 | 结束本次、等候、补谈申请；不自动具备管理员权 |
| 分组管理员 | 所授权组、来访队列和异常 | 接待、请求补位/延长、处理本组故障、请求支援 |
| 总主持人/授权调度员 | 本场必要调度数据和异常 | 分发、交棒、代管、调度及撤销；不得隐身监听 |
| 导师 | 自己预约与被邀请组的必要信息 | 请求加入；成员看见身份后按活动政策同意 |
| 投资人/旁听者 | 授权舞台、公开项目 | 观看；双方同意后另行申请一对一，旧链接不授予私聊权 |

每人单独确认报名时真实姓名，保留 Unicode 与原始显示形式，不强制分姓/名、不强制至少两个字。不用展示名当身份主键；同名显示项目或活动角色。本人声明与组织者核验分别记录，只有授权核验者能改核验标记。签到与媒体名牌、队列和操作日志统一使用活动姓名快照。真实姓名只在参会和授权管理范围展示。

预约对象只获知“未签到、上一场未结束、本人准备好、连接中、双方连入、暂时离线、状态待确认”等必要状态，不返回第三人的姓名、会议 ID、房内内容或其他行程。客户端心跳在线不能代表本人愿意提前开始。心跳 15 秒、45 秒未更新视为待确认是初始配置建议；显示最后更新时间。媒体状态必须来自服务端确认的媒体连接事件，断线不自动记缺席。

## 复用排班，增加执行数据

输入是已有发布排班及其版本，包含活动、轮次、配对、房间和原计划起止。默认 6 轮，每轮 15 分钟，轮间 2 分钟，可按活动配置。既有动态规划和六轮去重不在本次重写；单向/开放介绍仍沿用既有同意规则。发起人的逻辑房间固定，每次私聊使用独立媒体会话/代次，防止旧链接接入下一对。

拟新增执行对象（取得 schema 后再决定表名与迁移）：

| 对象 | 关键字段与约束 |
|---|---|
| 活动执行实例 | 既有活动 ID、发布排班版本、阶段、配置、递增 revision |
| 会面执行 | 既有配对 ID、原计划起止、调整后的安排、实际连通/结束、原因、状态 |
| 活跃席位 | account ID 唯一、会面 ID、设备代次、租约；跨活动也最多一个私聊 |
| 房间占用 | 活动/逻辑房间唯一、会面 ID、媒体代次、当前控制人 |
| 本人意愿 | 会面、account、提前同意、自动转场选择、手动离场标记、时间及有效版本 |
| 交棒命令 | 作用房间、现任/下一任主持、倒计时、版本、媒体执行确认 |
| 审计/事件发件箱 | 幂等 command ID、操作者、版本、事件类型、服务端时间、最小必要 payload |

报名、签到、进入授权房间、双方媒体连通、离开分别记事件。双方实际连通才记 actualStartedAt；实际断开/结束记 actualEndedAt，断线区间另记，不将整个窗口计作连续通话。无媒体确认时实际时长为未知。服务端下发 serverNow、截止时刻和 revision；客户端用往返时延校准显示，后台计时器只负责显示，服务器裁定换轮和截止。

建议每场用持久化协调器串行接受命令，跨场 account 席位还需要全局唯一约束。可以评估 Durable Object 与 D1，但必须根据现有认证、事务和部署能力落定，不能假设多个对象调用天然原子。所有安排变更带 expectedRevision、幂等键。占人、占房、更新会面、追加事件在同一可验证事务边界完成；两位运营同时调同一个人只接受一个，另一位得到冲突和最新状态。

## 状态、进入及媒体隔离

会场阶段：签到 → 开场演示 → 分组/轮转 → 全场成果 → 结束。晚到和重连请求服务器最新阶段。每组另有演示中 → 交棒待执行 → 分组中；连接异常是单独健康维度，不把“请求成功”当作交棒成功。收到媒体撤销及管理员准备确认后才显示“已交棒”。

会面状态：计划 → 等候 → 可进入 → 连接中 → 会谈中 → 结束/跳过/补谈待定。人在设备在线状态之外另有本人意愿。调度和媒体授予都只允许服务端执行，URL 不是授权凭证。

| 情况 | 执行规则及用户反馈 |
|---|---|
| 提前结束 | 任一人可随时离开；结束本次使该会话关闭，另一人收到通知并进入等候。双方均可主动结束，无强迫继续。提示休息、记笔记或申请提前见面，后续时段不变 |
| 提前开始 | 双方针对同一会面/版本明确同意、均已离开上一场、目标房间已释放、无既有冲突才占位。媒体连入后记录实际时间。后续六轮不平移；新调度或退出使旧同意失效 |
| 等人 | 从计划开始且自己已准备等候的较晚时刻计等待，显示原计划时间。默认 120 秒触发求助入口及主持异常，可配置。显示最近状态或“状态待确认”，可登记补谈，不自动缺席 |
| 上一场未结束 | 下一位留在个人候场，仅连状态服务，不获得私聊媒体 token。显示“上一场收尾中”；无预览画面、声音、字幕或轨道元数据 |
| 硬截止 | 一分钟、十秒提醒；服务端截止撤销旧房媒体。收到撤销确认前不放行下一对。失败则房间阻塞并告警，不能让前后两场重叠 |
| 延长 | 主持人预览具体受影响人、后续时段及空档后确认；写入新版本并通知所有受影响者。不能静默顺延整表，不能撞上对方另一场 |
| 断线/换设备 | 重新鉴权并读取最新安排，替换设备代次、撤销旧设备媒体后才发新凭证；待确认而非缺席。上一轮已结束时拒绝旧凭证，进入当前安排 |
| 跳过/手动离开 | 持久化 opt-out，撤销席位与媒体。自动转场不得覆盖；本人明确重新入场才恢复。网络中断不得错误推断为手动退出 |
| 管理员/旁听加入 | 必须另行授权且显示身份；双方私聊默认只允许双方。导师等例外加入须显示通知并按活动规则取得同意，记录授权及离开 |

媒体和数据库不能构成单一事务，因此使用可恢复的“撤销旧媒体 → 确认 → 释放席位 → 授予新媒体”流程及发件箱重试。未确认时封闭新入口，人工处理异常。租约过期只触发核对，不直接认定旧媒体断开；服务端故障恢复后先对账再开门。过期 token 本身不保证已建立的媒体连接断开，必须通过媒体端断开/权限撤销验证。服务器没有可靠的截止机制时不能上线一对一换轮。

总主持人演示源只含主持人音轨与 presentation，共享屏幕系统音频要单独确认浏览器支持。每个分组有独立接收授权；A 交棒时服务端移除 A 的演示分发并确认，B 保持演示。A 的私聊轨道绝不转发到演示源或 B。换轮、收回演示和召回同样需要媒体确认；只在浏览器静音不满足隔离要求。

## 四类活动与会后

| 活动 | 执行方式 |
|---|---|
| 女性共创 | 从既有六轮排班导入个人议程，固定发起人逻辑空间；不额外生成另一份匹配结果 |
| AI / 非 AI 快闪 | 开题 → 数小时团队工作 → 导师请求巡组 → 全场成果；团队工作不套用十五分钟截止 |
| 导师答疑 | 固定导师队列，显示基于已知安排的预计等待及不确定性；材料引用原项目/资源权限，不能因入会扩大可见范围 |
| 路演 | 舞台、候场和观众分权；台前剩余组数可见，最多十人发流为设计目标。观众只订阅，双方同意后创建独立私聊授权 |

会后“补谈/试合作/暂不继续”仅本人可见。双方同意后才调用既有邀请、接受及运营审核流程；保留本场最多确认一个团队和幂等建队事务，不以通话完成替代接受。接入现有团队工作台并核验成员权限。默认不录制，不保留媒体内容；不增加 emoji、反应、举手，不用摄像头或发言时长评分。设备测试、弱网纯音频、私下求助与通知保留。

部署须在真实源码完成鉴权、迁移回滚方案、媒体适配、服务端状态测试和真实设备彩排后进行。开发期间只用合成身份和项目；生产真实会员资料不复制到本仓库。生产发布前保留当前版本和迁移兼容窗口；入口使用按活动启用的功能开关，发生隔离/换轮故障时关闭新增入场并通知主持人，不能静默切回公开会议链接。

## 快闪团队编组

总主持人在调度台选择本期已录取的成员。报名技能只作标注参考。成员签到时可自选「有 idea」「无 idea · 方向待定」「Builder · 产品开发」「Seller · 销售」或留待标注。主持人也可在成员签到前批量设置标签。旁听者不进入组队名单。编组仅在本场或本次彩排内生效，保留主站已有团队关系。

全选有 idea 的成员并分发，会给每人建立一个独立团队。全选 Builder、Seller、全部无 idea 或全体成员后，均衡模式按名单顺序分配，随机模式打乱成员与候选组次序，A–Z 模式按姓名排序，中文使用拼音顺序。三种模式都优先补到同角色人数较少的组，再看总人数。未选中的人保留原位置。主持人可拖动一个姓名，或在手机上勾选多人后指定目标组。每组显示 Builder、Seller 和总人数。

草稿只有当前主持人可见，发布前展示改动成员及目标。服务端按版本接受完整的一次发布，冲突时要求重载。进入讨论仍由交棒操作触发。「开始所有创意组讨论」列出影响范围，同时保留主会场的演示。发起人默认接棒，离线时按原有规则由主持人指定替补。调动正在讨论的成员会更新原组的媒体房间，原组成员重新连接并可再次开启麦克风，目标组继续使用原有媒体房间。只有主持人可查看完整分组和标签，参会者在自己的会场看到分配结果。
